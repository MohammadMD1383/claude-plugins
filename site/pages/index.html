Claude Code plugins that keep your usage limits in view

Claude Code can't see your claude.ai 5-hour and weekly limits. These plugins fix that: usage-guard makes Claude conserve, checkpoint and write a hand-off before it gets cut off, and usage-bar shows context and limit usage right above the prompt.

Plugins

Each plugin is self-contained, installs from the same marketplace, and can be used alone or together.

usage-guard v{{v:usage-guard}}

Usage-limit awareness for Claude. It stays silent at normal usage, then makes Claude work lean, write HANDOFF.md and commit before the limit hits.

  • Zero tokens while usage is normal
  • Burn-rate projection, not just a percentage
  • Emergency snapshot if the limit hits mid-task
/plugin install usage-guard@{{market}}

usage-bar v{{v:usage-bar}}

A one-line bar above the prompt: context window used/total and the 5-hour and weekly limits with reset countdowns. Every section is optional.

  • Context updates after every model request
  • Yellow at 70%, red at 90% (configurable)
  • No scripts, no network calls, no context cost
/plugin install usage-bar@{{market}}

Install

Add the marketplace once, then install whichever plugins you want. Run these inside Claude Code.

  1. Add the marketplace 
    /plugin marketplace add MohammadMD1383/claude-plugins
  2. Install a plugin 
    /plugin install usage-guard@{{market}}
/plugin install usage-bar@{{market}}
  3. Optional: give usage-guard live limit data 
    /usage-guard:setup

    This taps Claude Code's status line feed, which carries exact limit data on every response. Your existing status line is kept.

Prefer the shell, or setting up a team? See the full guide to installing Claude Code plugins.

Why these exist

On Pro and Max plans, Claude Code runs against a 5-hour window and a weekly window. The model has no idea where you are in either, so it will happily start a 50-step refactor at 92% and stop mid-edit.

  • No half-applied workusage-guard has Claude commit in small steps and keep a hand-off note current as the limit approaches.
  • Resume anywhereHANDOFF.md is written for a reader with no context: Codex, a human, or the next Claude session.
  • See it before it bitesusage-bar puts context size, 5-hour and weekly usage, and reset countdowns in one line.
  • Cheap by designNo MCP servers, no always-on prompts. usage-guard adds 0 tokens at normal usage; usage-bar adds none at all.
  • Local and privateNo telemetry. usage-bar makes no network calls; usage-guard only reads the same endpoint /usage does, and only as a fallback.
  • TestedBoth plugins ship with test suites that run in CI on every push.

FAQ

Are these plugins free?

Yes. Both plugins are free and open source under the MIT license. You need Claude Code and, for the usage-limit features, a Claude Pro or Max plan.

Are these official Anthropic plugins?

No. They are independent community plugins by MohammadMD1383 and are not affiliated with or endorsed by Anthropic. The source code is public on GitHub.

What is the difference between usage-guard and usage-bar?

usage-guard changes what Claude does: it warns Claude as limits approach so it conserves budget, checkpoints and writes a hand-off. usage-bar changes what you see: a status bar with context size and limit usage. They work well together.

Do the plugins use up my tokens or context?

usage-bar adds nothing to Claude's context. usage-guard adds zero tokens while usage is normal and only sends short messages once a threshold is crossed; the full wrap-up message is about 225 tokens.

Do they work with an API key, Bedrock or Vertex?

Plan usage limits only exist on claude.ai Pro and Max subscriptions. With an API key, Bedrock or Vertex, usage-bar shows only the context section and usage-guard has no limit data to act on.
