# claude-plugins

A collection of [Claude Code](https://claude.com/claude-code) plugins by [MohammadMD1383](https://github.com/MohammadMD1383).

**Website:** [mohammadmd1383.github.io/claude-plugins](https://mohammadmd1383.github.io/claude-plugins/): a page for every plugin, plus [guides](https://mohammadmd1383.github.io/claude-plugins/guides/).

## Install

Add the marketplace once, then install whichever plugins you want:

```text
/plugin marketplace add MohammadMD1383/claude-plugins
/plugin install <plugin>@mohammadmd-plugins
```

## Repository layout

```text
.claude-plugin/marketplace.json   marketplace catalog (lists every plugin)
plugins/<name>/                   one self-contained plugin per directory
  .claude-plugin/plugin.json
  README.md, hooks/, skills/, scripts/, tests/ ...
site/                             the website (GitHub Pages), see below
.github/workflows/test.yml        CI
.github/workflows/pages.yml       builds and deploys the website on push to main
```

## Adding a plugin

1. Create `plugins/<name>/` with `.claude-plugin/plugin.json` (`name`, `version`, `description`) and a `README.md`.
2. Add an entry to `.claude-plugin/marketplace.json` with `"source": "./plugins/<name>"`, a short `description` and a `category`.
3. If it has `tests/`, add a job for it to `.github/workflows/test.yml`.
4. Run `python3 site/build.py --sync`. It regenerates the plugin table above and checks everything below.

The website picks the plugin up on its own: its page is generated from its README, and it is added to the home page, `/plugins/`, the footer, the sitemap and `llms.txt`. For extra search-focused content (a custom title, card highlights, an FAQ), add a sidecar `site/pages/plugins/<name>.html`; see the existing ones.

## Website

`site/` is a static site generator with no dependencies (Python 3.9+, stdlib only) that turns the repository into the website. To avoid drift, it repeats nothing the repo already says:

| On the site | Comes from |
| --- | --- |
| Plugin list, cards, categories, versions, install commands | `.claude-plugin/marketplace.json` and each `plugin.json` |
| Plugin pages | each plugin's `README.md` (links to repo files go to GitHub, links to other plugins go to their pages) |
| "Updated" dates and sitemap `lastmod` | the git history of each page's sources |
| Social images | rendered for every page on each deploy |
| Plugin table in this README | generated by `--sync` |

Guides and other pages live in `site/pages/**/*.html` as a JSON `<!--meta-->` header plus body HTML.

```bash
python3 site/build.py --sync --base-url http://localhost:8000   # -> _site/
python3 -m http.server -d _site                                 # preview at http://localhost:8000/
```

The build fails, and so does CI, when the repo and the site disagree:

- marketplace and `plugin.json` names don't match, or a version, description or README is missing;
- a README links to a file that doesn't exist, or a site link or `#anchor` is broken;
- any README or page mentions a `/<plugin>:<command>` the plugin doesn't have, or a `<plugin>@mohammadmd-plugins` that isn't in the marketplace;
- a plugin has `tests/` that CI never runs;
- the plugin table in this README is out of date.

The build also adds canonical, Open Graph and JSON-LD tags to every page, writes a Markdown copy of each page (`index.md`) plus `llms.txt` and `llms-full.txt` for AI agents, and generates `sitemap.xml` and `robots.txt`. To preview social images locally, run `NODE_PATH="$(npm root -g)" node site/tools/render-images.cjs` (needs Playwright). The deploy workflow reads the repository variables `GOOGLE_SITE_VERIFICATION`, `BING_SITE_VERIFICATION` and `INDEXNOW_KEY`.
